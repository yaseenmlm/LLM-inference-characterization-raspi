LLM inference · Raspberry Pi 5 and Ryzen 7 7700X

Memory sets the ceiling. It isn't always the limit.

Each generated token reads about every model weight once, so decode speed can't beat read bandwidth ÷ model size. I predicted that ceiling from measured bandwidth, then ran 7 models on two machines to see how close they got.

01 · The prediction

No run beats its ceiling

Each dot is one model's measured decode speed. The dashed line is the ceiling for the picked machine and thread count. Both axes are log scales, so the ceiling is a straight line. On the Pi at 4 threads every model sits close to it. Pick the 7700X at 8 threads to see the gap open up.

02 · Adding threads

On the Pi, threads help until memory runs out. On the PC, they hurt.

Decode speed for each model as threads are added, on one shared scale. On the Pi, Qwen Q2 is CPU-limited and keeps speeding up, while Qwen Q8 is memory-limited from the first thread. On the 7700X, 6 of 7 models are fastest at 1 or 2 threads.

03 · Where the PC's time goes

The lost time is per layer, not per byte

Each token's time minus what the ceiling predicts, divided by the model's layer count. Q8 is 2.4 times the size of Q2, yet both lose the same time per layer. The loss grows with threads, which points to threads waiting for each other rather than to memory. Qwen 7B loses less, and I don't know why yet.

04 · The input

Read bandwidth, measured on each machine

The mean of 3 repeats of a read-only test over 1 GiB. This is the number the ceiling divides by. The Pi's falls as threads are added. The PC's barely changes after 2 threads.
